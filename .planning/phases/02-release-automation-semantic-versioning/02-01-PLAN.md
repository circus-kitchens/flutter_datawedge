<objective>
Establish two pre-conditions required before the release workflow can function:

1. Create the v3.0.0 baseline git tag on the original fork commit (before Phase 1 changes). mtrust-api-guard compares current HEAD against this tag to detect API changes. Without this tag, it has no reference point and will produce wrong versions or fail.

2. Create CHANGELOG.md in the repo root with a standard Keep a Changelog header. The release workflow will append entries via mtrust-api-guard. Starting with an empty-entries file (header only, per D-10) ensures first automated release produces a clean changelog.

Purpose: These are mandatory pre-conditions for release automation. The release workflow (Plan 02) cannot function correctly without them.

Output: v3.0.0 git tag on original fork commit + CHANGELOG.md committed to main.
</objective>
