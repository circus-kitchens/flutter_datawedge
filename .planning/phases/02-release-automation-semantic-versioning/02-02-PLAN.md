<objective>
Create the GitHub Actions release workflow at `.github/workflows/release.yml`. This is the core deliverable of Phase 2: a 4-job workflow that gates release automation behind CI checks, then runs mtrust-api-guard to detect API changes, bumps pubspec.yaml version, creates an annotated git tag, updates CHANGELOG.md, and publishes a GitHub Release.

Purpose: Every push to main that contains public API changes automatically produces a tagged, versioned, documented release. Developers never manually set version numbers or write changelog entries.

Output: `.github/workflows/release.yml` committed and pushed. First run after merge will produce a v3.1.0 (or appropriate semver) release.
</objective>

```yaml
env:
  FLUTTER_CHANNEL: "stable"

jobs:
  lint:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Flutter Setup
        uses: subosito/flutter-action@v2
        with:
          cache: true
          channel: ${{ env.FLUTTER_CHANNEL }}
      - name: Dependencies
        run: flutter pub get
      - name: Dart Analyze
        uses: invertase/github-action-dart-analyzer@v1
        with:
          fatal-infos: true
          fatal-warnings: true
          annotate: true
      - name: Check Formatting
        run: dart format --set-exit-if-changed --output none $(find lib test -name "*.dart" -not \( -name "*.freezed.dart" -o -name "*.g.dart" \))

  android-build:
    needs: [lint]
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Flutter Setup
        uses: subosito/flutter-action@v2
        with:
          cache: true
          channel: ${{ env.FLUTTER_CHANNEL }}
      - name: Java Setup
        uses: actions/setup-java@v4
        with:
          distribution: "temurin"
          java-version: "17"
      - name: Dependencies
        run: flutter pub get
      - name: Build Android Example APK
        run: cd example && flutter build apk --release

  test:
    needs: [lint]
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Flutter Setup
        uses: subosito/flutter-action@v2
        with:
          cache: true
          channel: ${{ env.FLUTTER_CHANNEL }}
      - name: Dependencies
        run: flutter pub get
      - name: Run Tests
        run: flutter test
```

Note: The release.yml lint job uses `dart analyze` (not invertase/github-action-dart-analyzer) because annotate: true requires write permissions on check suites that are only relevant for PRs. The release.yml runs on push to main where standard dart analyze output is sufficient.

    **CRITICAL IMPLEMENTATION DETAILS:**

    1. **Triggers (D-01, D-02, D-05):**
       - `push: branches: [main]` — automatic on merge to main
       - `paths-ignore` excludes: `.github/workflows/**`, `*.md`, `CHANGELOG.md`, `.gitignore` — prevents spurious releases on CI/doc changes (Pitfall 4 from research)
       - `workflow_dispatch:` — manual fallback

    2. **Permissions (D-12, Pitfall 6 from research):**
       - `permissions: contents: write` — required for tag push and GitHub Release creation

    3. **lint job:** Copy from pull_request.yml but replace `invertase/github-action-dart-analyzer@v1` with `run: dart analyze` (annotation support irrelevant for push events)

    4. **android-build job:** Copy exactly from pull_request.yml with `needs: [lint]`

    5. **test job:** Copy exactly from pull_request.yml with `needs: [lint]`

    6. **release job (D-03, D-04, D-06, D-13, D-14):**
       - `needs: [lint, android-build, test]` — gates on all CI jobs
       - `runs-on: ubuntu-latest`, `timeout-minutes: 20`
       - Checkout step MUST use `fetch-depth: 0` — full git history for tag lookup (Common Mistake 1 from research)
       - Activate mtrust-api-guard: `dart pub global activate mtrust_api_guard 6.0.4`
       - Run mtrust-api-guard: `mtrust-api-guard --input pubspec.yaml --output .bump-result.json`
       - Validate JSON output exists before parsing (Pitfall 5 from research)
       - Extract `change_type`, `new_version`, `changelog` from JSON via jq
       - Graceful skip if `change_type == 'none'` (D-13): print "No API changes detected. Skipping release." and exit 0
       - Idempotency check (D-14): `git rev-parse "v$VERSION" >/dev/null 2>&1` — if tag exists, print message and skip
       - Configure git (Pitfall 3 from research): `git config user.email "github-actions[bot]@users.noreply.github.com"` and `git config user.name "github-actions[bot]"`
       - Update pubspec.yaml version: `sed -i "s/^version: .*/version: $VERSION/" pubspec.yaml`
       - Append changelog entry to CHANGELOG.md: inject entry after the header comment line using `sed` or `awk`
       - Commit: `git add pubspec.yaml CHANGELOG.md && git commit -m "chore: release $VERSION"`
       - Create annotated tag: `git tag -a "v$VERSION" -m "Release v$VERSION"` (D-04)
       - Push with tags: `git push origin main --tags`
       - Create GitHub Release via gh CLI (D-11): `gh release create "v$VERSION" --title "Release $VERSION" --notes "$CHANGELOG" --target main`
       - Release Summary step (always): log change_type, version, tag_exists status

    **CHANGELOG.md update approach:**
    Insert the changelog entry from mtrust-api-guard after the last line of the header (after the HTML comment). Use a temp file approach:
    ```bash
    ENTRY="${{ steps.version.outputs.changelog }}"
    # Insert entry after the <!-- comment --> line
    awk '/<!-- Entries below/{print; print ""; print "'"$ENTRY"'"; next}1' CHANGELOG.md > CHANGELOG.tmp && mv CHANGELOG.tmp CHANGELOG.md
    ```
    This preserves the header and prepends new entries at the top of the entries section.
