## Directory Purposes

**lib/**
- Purpose: Public Dart API surface and internal implementation
- Contains: Package entry points, models, logger, main service class
- Key files: `flutter_datawedge.dart` (main API), `logger.dart` (logging), `src/pigeon.dart` (generated bridge)

**lib/src/**
- Purpose: Internal implementation details (not directly imported by users)
- Contains: Core `FlutterDataWedge` class, decoder lists, Pigeon-generated code
- Key files: `flutter_datawedge.dart` (100+ lines with all public methods), `pigeon.dart` (2000+ lines generated)

**lib/src/models/**
- Purpose: Immutable data classes and enums for configuration and events
- Contains: `ScanResult`, `ScanEvent`, `ScannerStatus`, `ActionResult`, `FlutterDatawedgeException`
- Key files: All use Freezed annotations for immutability and JSON serialization

**android/**
- Purpose: Android native platform implementation
- Contains: Flutter plugin lifecycle, broadcast receiver, configuration builders
- Key files:
  - `FlutterDatawedgePlugin.kt`: Plugin lifecycle setup
  - `DWInterface.kt`: Core Android logic (450+ lines)
  - `BuildBarcodeConfig.kt`, `BuildIntentConfig.kt`: Configuration transformation

**android/.../pigeon/**
- Purpose: Auto-generated Kotlin code from Pigeon interface
- Contains: `DataWedgeHostApi`, `DataWedgeFlutterApi` implementations, all DTOs
- Generated by: `./generate.sh` from `pigeons/datawedge_pigeon.dart`
- Committed: Yes (part of build output)

**pigeons/**
- Purpose: Pigeon interface definitions (source of truth for platform channels)
- Contains: Dart classes and enums that define the contract between Dart and Kotlin
- Key files: `datawedge_pigeon.dart` (450+ lines with all data classes and API methods)

**example/**
- Purpose: Reference application demonstrating package usage
- Contains: Minimal app with profile setup, scan listening, and status monitoring
- Key files:
  - `main.dart`: Shows initialization sequence and stream setup
  - `button_tab_view.dart`: UI for controlling scanner (enable/disable/suspend)

## Key File Locations

**Entry Points:**

- `lib/flutter_datawedge.dart`: Package public API (barrel exports)
- `lib/src/flutter_datawedge.dart`: Main `FlutterDataWedge` singleton class (180+ lines)
- `android/.../FlutterDatawedgePlugin.kt`: Android plugin entry point (41 lines)

**Configuration:**

- `pubspec.yaml`: Package metadata, dependencies, Flutter plugin declaration
- `analysis_options.yaml`: Dart analyzer strictness settings (very_good_analysis preset)
- `android/build.gradle`: Android build configuration
- `generate.sh`: Pigeon code generation command

**Core Logic:**

- `lib/src/flutter_datawedge.dart`: Profile management, decoder control, plugin state, event streams
- `android/.../DWInterface.kt`: Intent reception, payload parsing, configuration dispatch
- `pigeons/datawedge_pigeon.dart`: Platform channel contract and DTO definitions

**Data Models:**

- `lib/src/models/scan_result.dart`: Barcode scan data (3 fields: data, labelType, source)
- `lib/src/models/scanner_status.dart`: Device state with enum (4 states: WAITING, SCANNING, IDLE, DISABLED)
- `lib/src/models/action_result.dart`: API response with success computation (4 fields)
- `lib/src/models/flutter_datawedge_exception.dart`: Base and derived exceptions

**Testing:**

- `example/test/flutter_datawedge_test.dart`: Platform channel integration tests
- `example/test/widget_test.dart`: Widget tests for example app

## Naming Conventions

**Files:**

- Dart files: `snake_case.dart` (e.g., `flutter_datawedge.dart`, `scan_result.dart`)
- Kotlin files: `PascalCase.kt` (e.g., `DWInterface.kt`, `BuildBarcodeConfig.kt`)
- Generated files: Suffixed with use (e.g., `pigeon.dart`, `Pigeon.kt`)

**Directories:**

- Dart: `snake_case` (e.g., `lib/src/models/`)
- Kotlin: `lowercase` packages (e.g., `com/circuskitchens/flutter_datawedge/`)

**Classes:**

- Dart: `PascalCase` (e.g., `FlutterDataWedge`, `ScanEvent`, `Logger`)
- Kotlin: `PascalCase` (e.g., `DWInterface`, `BuildBarcodeConfig`)

**Enums:**

- Dart: `PascalCase` members (e.g., `ConfigMode.update`, `ScannerState.scanning`)
- Kotlin: `UPPERCASE` constants for DataWedge strings, enum member `PascalCase`

**Methods:**

- Dart: `camelCase` (e.g., `createProfile()`, `enableAllDecoders()`, `setConfig()`)
- Kotlin: `camelCase` (e.g., `buildBarcodeConfig()`, `setupBroadcastReceiver()`)

## Where to Add New Code

**New Scanner Configuration Feature:**
- Primary code: `lib/src/flutter_datawedge.dart` (add public method)
- Pigeon definition: `pigeons/datawedge_pigeon.dart` (add to `DataWedgeHostApi` abstract class)
- Android implementation: `android/.../DWInterface.kt` (implement the new method)
- Android builder: New file `BuildXyzConfig.kt` if needed for complex configuration
- Regenerate: Run `./generate.sh` to update Pigeon bindings

**New Event Type:**
- Data class: `lib/src/models/new_event.dart` (use Freezed annotations)
- Pigeon definition: `pigeons/datawedge_pigeon.dart` (add Dart class)
- Dart callback: `lib/src/flutter_datawedge.dart` (override `DataWedgeFlutterApi` method)
- Stream: `lib/src/flutter_datawedge.dart` (add `StreamController` field and getter)
- Android dispatch: `android/.../DWInterface.kt` (onReceive() case handler)

**New Decoder or Enum:**
- Pigeon definition: `pigeons/datawedge_pigeon.dart` (add enum or expand existing)
- Android mapping: `android/.../Decoders.kt` or relevant builder (if not auto-generated)
- Regenerate: Run `./generate.sh`

**Utilities and Helpers:**
- Shared helpers: `android/.../BundleUtils.kt` (for Android) or `lib/logger.dart` pattern for Dart
- Package-wide: Use existing helper patterns (e.g., `intentBool()`, `intentNr()` in BuildBarcodeConfig)

## Special Directories

**lib/src/**
- Purpose: Private implementation details (prefix prevents auto-export)
- Generated: No
- Committed: Yes
- Note: All code here should be imported via `lib/flutter_datawedge.dart` barrel file

**android/src/main/kotlin/.../pigeon/**
- Purpose: Auto-generated Pigeon platform channel code
- Generated: Yes (by `./generate.sh`)

**lib/src/pigeon.dart**
- Purpose: Auto-generated Pigeon Dart platform channel code
- Generated: Yes (by `./generate.sh`)

## Build and Generation Workflow

**Code Generation:**
```bash
./generate.sh
```
This runs Pigeon to regenerate:
- `lib/src/pigeon.dart` (Dart platform channel bindings)
- `android/src/main/kotlin/.../pigeon/Pigeon.kt` (Kotlin platform channel bindings)

**Dependencies Management:**
```bash
flutter pub get              # Install/update dependencies
flutter pub upgrade          # Upgrade all dependencies
flutter pub upgrade pigeon   # Upgrade Pigeon specifically
```

**Running Tests:**
```bash
flutter test example/test/    # Run integration and widget tests
```

**Building Documentation:**
```bash
dart doc
```
